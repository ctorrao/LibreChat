# LibreChat Code Runner API Documentation

## Overview

This document describes the LibreChat Code Runner API (execute_code tool), which provides secure Python code execution capabilities. The API is hosted at `api.librechat.ai` and integrates with LibreChat to enable AI agents to execute code, process files, and generate outputs.

## Architecture

### Integration Flow

```
LibreChat Client
    ↓
LibreChat Server (/api/server/services/Files/Code/)
    ↓
@librechat/agents package (createCodeExecutionTool)
    ↓
Code Runner API (api.librechat.ai)
    ↓
Sandboxed Python Environment
```

### Key Components

**Server-Side Integration:**
- `/api/server/services/Files/Code/crud.js` - File upload/download operations
- `/api/server/services/Files/Code/process.js` - File processing and session management
- `/api/app/clients/tools/util/handleTools.js` - Tool initialization and configuration

**Tool Creation:**
```javascript
const CodeExecutionTool = createCodeExecutionTool({
  user_id: user,
  files: preppedFiles,
  CODE_API_KEY: apiKey
});
```

## API Endpoints

### 1. Upload File

**Endpoint:** `POST https://api.librechat.ai/upload`

**Purpose:** Upload files to make them available in the code execution environment.

**Request:**
```http
POST /upload HTTP/1.1
Host: api.librechat.ai
X-API-Key: your-api-key
User-Id: user-identifier
Content-Type: multipart/form-data

--boundary
Content-Disposition: form-data; name="entity_id"

optional-entity-id
--boundary
Content-Disposition: form-data; name="file"; filename="data.csv"
Content-Type: text/csv

[file content]
--boundary--
```

**Response:**
```json
{
  "message": "success",
  "session_id": "abc123def456",
  "files": [
    {
      "fileId": "file789xyz",
      "filename": "data.csv"
    }
  ]
}
```

**File Access in Code:**
Files are available at `/mnt/data/{filename}` in the execution environment.

### 2. Download File

**Endpoint:** `GET https://api.librechat.ai/download/{session_id}/{file_id}`

**Purpose:** Download files generated by code execution or retrieve uploaded files.

**Request:**
```http
GET /download/abc123def456/file789xyz HTTP/1.1
Host: api.librechat.ai
X-API-Key: your-api-key
User-Agent: LibreChat/1.0
```

**Response:**
- Binary file content
- Content-Type header indicates file type
- Files expire after ~24 hours

### 3. Get Session Files

**Endpoint:** `GET https://api.librechat.ai/files/{session_id}`

**Purpose:** List files in a session and check their status.

**Request:**
```http
GET /files/abc123def456?detail=summary HTTP/1.1
Host: api.librechat.ai
X-API-Key: your-api-key
User-Agent: LibreChat/1.0
```

**Query Parameters:**
- `detail`: `summary` or `full` (default: `summary`)
- `entity_id`: Optional filter by entity

**Response:**
```json
[
  {
    "name": "abc123def456/file789xyz",
    "lastModified": "2025-10-18T12:00:00Z"
  }
]
```

## Configuration

### Environment Variables

**Required:**
```bash
LIBRECHAT_CODE_API_KEY=your-api-key
```

Set this in your `.env` file to enable code execution capabilities.

### Authentication

The API uses two authentication mechanisms:

1. **API Key** (Required)
   - Header: `X-API-Key`
   - Value: Your LibreChat Code Runner API key

2. **User ID** (Tracking)
   - Header: `User-Id`
   - Value: LibreChat user identifier
   - Used for usage tracking and permissions

## File Management

### Upload Process

1. **File Preparation**
   ```javascript
   const { files, toolContext } = await primeCodeFiles(
     { tool_resources, req, agentId },
     codeApiKey
   );
   ```

2. **Automatic Re-upload**
   - Files are checked for session validity (active within 23 hours)
   - Expired files are automatically re-uploaded
   - Session information is cached in file metadata

3. **File Metadata**
   ```javascript
   {
     file_id: "uuid",
     filename: "data.csv",
     metadata: {
       fileIdentifier: "session_id/file_id?entity_id=xxx"
     }
   }
   ```

### Download Process

Images generated by code execution are automatically:
1. Downloaded from Code Runner API
2. Converted to optimized format
3. Stored using LibreChat's file strategy
4. Associated with the message/conversation

Non-image files return a filepath reference:
```javascript
{
  filename: "output.txt",
  filepath: "/api/files/code/download/session_id/file_id",
  expiresAt: timestamp + 24h,
  conversationId: "conv-id",
  toolCallId: "call-id",
  messageId: "msg-id"
}
```

## Session Management

### Session Lifecycle

1. **Creation**: New session created on first file upload
2. **Active Period**: ~23 hours from session creation
3. **Expiration**: Files become unavailable after ~24 hours
4. **Cleanup**: Automatic cleanup by Code Runner service

### Session Validation

```javascript
function checkIfActive(dateString) {
  const givenDate = new Date(dateString);
  const currentDate = new Date();
  const timeDifference = currentDate - givenDate;
  const hoursPassed = timeDifference / (1000 * 60 * 60);
  return hoursPassed < 23;
}
```

### File Priming

Before code execution, LibreChat:
1. Checks all file sessions for activity
2. Re-uploads expired files
3. Updates file metadata with new session info
4. Provides file context to the AI agent

**Tool Context Example:**
```
- Note: The following files are available in the "execute_code" tool environment:
    - /mnt/data/data.csv
    - /mnt/data/analysis.py (just attached by user)
```

## Code Execution

### Tool Integration

The execute_code tool is created using `@librechat/agents`:

```javascript
const CodeExecutionTool = createCodeExecutionTool({
  user_id: userId,
  files: [
    {
      id: "file789xyz",
      session_id: "abc123def456",
      name: "data.csv"
    }
  ],
  CODE_API_KEY: apiKey
});
```

### Execution Environment

- **Language**: Python 3.x
- **Environment**: Sandboxed, isolated containers
- **File Access**: `/mnt/data/` directory
- **Network**: Restricted or no external access
- **Libraries**: Common data science packages pre-installed

### Code Execution Flow

1. Agent decides to use execute_code tool
2. Code is sent to Code Runner API
3. Execution happens in sandboxed environment
4. Outputs (stdout, stderr, files) are captured
5. Results returned to LibreChat
6. Generated files processed and stored

## Error Handling

### Common Errors

**401 Unauthorized**
```json
{
  "error": {
    "message": "Invalid API key",
    "code": "UNAUTHORIZED"
  }
}
```

**404 Not Found**
```json
{
  "error": {
    "message": "Session not found or expired",
    "code": "NOT_FOUND"
  }
}
```

**413 Payload Too Large**
```json
{
  "error": {
    "message": "File size exceeds 150 MB limit",
    "code": "PAYLOAD_TOO_LARGE"
  }
}
```

### Error Recovery

LibreChat implements automatic recovery:

```javascript
try {
  const stream = await getDownloadStream(req, file.filepath);
  const fileIdentifier = await uploadCodeEnvFile({
    req,
    stream,
    filename: file.filename,
    entity_id: queryParams.entity_id,
    apiKey
  });
  // Update file metadata
} catch (error) {
  logger.error(`Error re-uploading file: ${error.message}`);
}
```

## Security Considerations

### API Key Protection

- Never expose API keys in client-side code
- Store in environment variables only
- Rotate keys periodically

### Sandboxing

- Code executes in isolated containers
- Limited resource access
- No persistent storage between sessions

### File Access Control

- Files are scoped to sessions
- Session IDs are unpredictable UUIDs
- 24-hour automatic expiration

### User Permissions

LibreChat checks permissions before allowing code execution:

```javascript
const hasPermission = await checkAccess({
  user: req.user,
  permissionType: PermissionTypes.RUN_CODE,
  permissions: [Permissions.USE],
  getRoleByName
});
```

## Limitations

### Resource Limits

- **File Size**: Maximum 150 MB per file
- **Session Duration**: ~24 hours
- **Execution Time**: Subject to API limits
- **Memory**: Limited by sandbox environment

### File Persistence

- Files are temporary (24-hour retention)
- No long-term storage
- Must re-upload for new sessions

### Network Access

- Sandboxed environments may have restricted network access
- Cannot make arbitrary external API calls
- Pre-installed libraries only
